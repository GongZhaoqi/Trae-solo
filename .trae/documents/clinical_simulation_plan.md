# 临境推演：临床决策实训全链路闭环平台

## 项目概述

**临境推演**是基于多模态感知与 Graph-RAG 驱动的临床决策实训全链路闭环平台，核心是以代价体验机制解决知行断层问题。

### 核心特点

| 特点 | 描述 |
|------|------|
| 案例真实训练 | 学生实习反馈直接回流，病案案例库越练越真 |
| 剧本智能生成 | 多模态学习数据生成动态完善剧本，千人千面 |
| 犯错沉浸体验 | 模拟真实临床风险，错误即时呈现后果 |
| 医学智能导师 | 精准画像定位薄弱项，定制个人成长路径 |

## 功能模块划分

### 1. 病例剧本管理系统

**核心业务流程：**
1. **病例输入** → AI自动生成完整剧本 → AI生成配套写实贴图
2. **剧本内容**：学生体验完整护理程序（问诊→评估→诊断→护理措施）
3. **交互方式**：大部分采用选项选择（降低运行压力），关键健康史支持语音输入
4. **实操环节**：选择最重要的护理措施进行学生实操

**功能：**
- 病例剧本的创建、编辑、发布
- AI自动生成剧本（基于输入病例）
- AI生成写实贴图（配套病例场景）
- 剧本模板管理
- 多维度标签分类
- 剧本版本控制
- 护理程序节点定义（问诊、评估、诊断、护理措施）

**文件结构：**
```
backend/app/cases/
├── routers/          # API路由
├── services/         # 业务逻辑
│   └── ai_generator.py  # AI剧本生成
├── schemas/          # 数据模型
└── repositories/     # 数据访问
```

**剧本生成流程：**
```
输入病例信息 → AI分析病例 → 生成护理程序剧本 → AI生成场景贴图 → 剧本审核发布
     │                    │                    │
     ▼                    ▼                    ▼
 患者基本信息        病情分析              场景可视化
 病史描述            护理要点              写实贴图
 检查结果            风险评估              角色形象
```

### 2. 多模态数据采集系统

**技术方案：采用 Google MediaPipe 框架**

**核心应用场景（基于临床实训需求）：**
1. **关键健康史采集环节**：通过表情识别检测学生紧张情绪，动态调整病例难度（刁难机制）
2. **护理操作环节**：识别学生表情和动作是否准确、干净、规范
3. **语音交互**：关键健康史采集支持语音输入

**功能：**
- 实时视频流采集与处理（摄像头）
- 人脸检测与表情识别（MediaPipe Face Mesh）→ 紧张情绪检测
- 手部姿态与操作识别（MediaPipe Hands）→ 护理操作规范评估
- 全身姿态估计（MediaPipe Pose）→ 肢体语言分析
- 语音数据采集与识别（Google Speech-to-Text）→ 病史采集语音输入
- 操作行为记录与分析
- 生理指标模拟输入

**文件结构：**
```
backend/app/sensors/
├── video/            # 视频流处理（MediaPipe集成）
├── audio/            # 语音识别（Google STT）
├── pose/             # 姿态分析（MediaPipe Pose）
├── expression/       # 表情识别与情绪分析（Face Mesh）
├── gesture/          # 手势识别（MediaPipe Hands）
├── behavior/         # 行为分析与难度调整
└── vitals/           # 生理指标
```

**Google MediaPipe 应用场景：**
| 功能 | MediaPipe模块 | 临床实训价值 | 具体应用 |
|------|--------------|-------------|---------|
| 表情识别 | Face Mesh | 分析学生情绪状态 | 检测紧张→触发刁难机制 |
| 手势识别 | Hands | 记录操作动作 | 评估护理操作准确性、干净度 |
| 姿态估计 | Pose | 评估肢体语言 | 问诊时的仪态评估 |
| 实时追踪 | Objectron | 追踪操作对象 | 模拟仪器操作追踪 |

**多模态驱动的自适应实训机制：**

**[应用一：情绪检测与学习评估]**
```
表情识别 → 分析紧张程度 → 关联知识掌握度
    ↓
紧张指数高 → 说明对应知识点掌握不足
    ↓
    ├─ 记录薄弱环节
    ├─ 纳入学习画像
    └─ 调整后续训练重点
```

**[应用二：动态难度调整（刁难机制）]**
```
检测到紧张情绪 → 系统触发"刁难"机制
    ↓
    ├─ 患者提问更具挑战性
    ├─ 病情信息更加复杂
    └─ 增加干扰因素
```

**[应用三：护理操作规范评估]**
```
手势识别 + 姿态估计 → 评估操作规范度
    ↓
    ├─ 动作准确性评分
    ├─ 操作干净度评估
    └─ 实时纠正提示
```

**多模态学习评估体系：**
| 评估维度 | 检测指标 | 评估意义 |
|---------|---------|---------|
| 情绪状态 | 紧张指数 | 反映知识点掌握程度 |
| 操作规范 | 手势准确性 | 评估操作技能水平 |
| 沟通能力 | 表情变化 | 分析病患沟通技巧 |
| 心理素质 | 情绪稳定性 | 评估临床抗压能力 |

### 3. Graph-RAG 决策引擎 + DP决策代价系统

**核心设计理念：**
- 每一次临床决策都有真实的"代价"
- 通过DP（决策点数）量化护理操作的成本
- 学生需要在有限的DP预算内完成最优护理方案

**功能：**
- 医保物价政策知识库
- 临床诊疗指南知识图谱
- 决策代价计算引擎
- 智能推理与推荐
- **DP决策代价评估系统**

**DP代价计算规则：**
| 操作类型 | DP消耗 | 说明 |
|---------|--------|------|
| 基础护理操作 | 5-10 DP | 如测量生命体征 |
| 专科护理操作 | 15-25 DP | 如导尿、吸痰 |
| 紧急抢救操作 | 30-50 DP | 如心肺复苏 |
| 医嘱执行 | 3-8 DP | 根据医嘱复杂度 |
| 护理评估 | 5-15 DP | 健康史采集、护理体检 |
| 护理记录 | 3-5 DP | 书写护理文书 |

**决策代价系统特点：**
- **资源有限性**：每个病例有固定的DP预算
- **代价可视化**：每项操作实时显示DP消耗
- **后果即时反馈**：错误决策导致资源浪费
- **最优路径探索**：鼓励学生寻找最优护理方案

**DP应用场景示例：**
```
[护理评估环节]
    ↓
学生执行健康史采集 → 消耗对应DP
    ↓
    ├─ 正确采集 → 获得诊断积分
    └─ 错误/遗漏 → DP浪费 + 扣分

[护理操作环节]
    ↓
学生选择护理措施 → 消耗对应DP
    ↓
    ├─ 选择最优措施 → DP效率高
    └─ 选择次优措施 → DP效率低 + 资源浪费
```

**文件结构：**
```
backend/app/engine/
├── knowledge/        # 知识图谱操作
├── reasoning/        # 推理引擎
├── cost_calc/        # 代价计算（DP系统）
├── rag/              # RAG检索
└── dp_manager/       # DP决策点管理
```
